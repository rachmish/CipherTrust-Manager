## CDP and CTE-U coverage notes

### Reference
**Source scope note**: file covers CDP (Oracle section only; DB2/SQL Server/Teradata/JDBC-SSL listed in TOC but absent) then CTE (CM-side admin). No dedicated CTE-U chapter; CTE-U appears only as a client type/license.
**CDP (CipherTrust Database Protection)**: GUI = Database Protection tile > Databases > + Add Database (wizard: Select Database Type > Connection details > Confirmation). Mgmt user must be in `ProtectDB Users` group (CDP Server Administrator). API: `POST /api/v1/auth/tokens/` {name,password[,domain]} -> jwt (300s); playground CDP > Database `/v1/protectdb/databases` (Add). Body: database_type,name,host,database_port,connection_Protocol,database_user,database_password,metadb_user,meta_password,database_name. Playground logout: 10 min idle / 30 min after closing browser. CLI: `pdbctl`, ksctl.
- Oracle conn fields: Name(Alias, unique), Host, Port (1521 TCP / 2484 SSL; SSL needs CA cert uploaded to CM), DB user (needs CREATE/MODIFY/DROP views, tables, triggers), MetaDB user fixed `INGRIAN` (pre-created before CDP client install), Enable Credentials Caching (off = prompt per session), Protocol TCP|SSL, Connect With SID|Service Name.
- User mapping = DB user/role -> CM local user (+password); stored in `ING_AUTHORIZED_USER` (metadata DB). Individual mapping beats role mapping; multiple roles -> alphabetically first role wins. Default mapping user `ING_DEFAULT_USER` (catch-all; give NO key/group perms; avoid that name for real users). No default + unmapped user = CDP returns error, nothing sent to CM. Domain users: `my-domain||admin`. Changed mapping needs new DB connection. Local mode + versioned key: local user must be in `Key Users` group and key shared with it. Same-IP aliases show same mappings.
- Role-based perms: users->groups (encryptGroup/decryptGroup)->key perms (remote mode only); map to DB users.
- Column props (Set Value): new col `<column>_NEW` (don't rename column after saving); Encryption Type Standard|FPE; Algos SEED,TDES-192,ARIA-128/192/256,AES-128/192/256 (FPE=AES only, non-versioned key only); Mode CBC(recommended)|ECB, FPE card `CARD10` (digits 0-9; other chars -> invalid input data error); IV hex: TDES 16 chars (8B), AES 32 chars (16B), FPE 112 chars (used if len>56); CBC needs IV, ECB disallows; Padding default PKCS5Padding (n/a FPE); FPE format NONE|FIRST_SIX|FIRST_SIX_LAST_FOUR|FIRST_TWO_LAST_FOUR|LAST_FOUR (effective data length must exceed retained digits); Tweak Algorithm NONE|SHA1|SHA256 (only SHA1/256 if format != NONE), Tweak data ASCII <=256 chars (hex for NONE). Unauthorized-user behavior: error "insufficient permissions" | NULL | replacement value | encrypted value.
**CTE concepts**: Components = CM (policies, keys, logs) + Agents on clients. Policy types: Standard, LDT, COS (S3; Linux), IDT (Teradata; XTS keys), CTE for Kubernetes (CBC-CS1 only). Policy = Security Rules + Key Rules + Data Transformation Rules (+Signature Rules, K8s only). Rules evaluated top-down, first full match wins; unspecified criteria = All; Effect required: Permit|Deny|ApplyKey|Audit. Criteria: Resource,User,Process,Action,Effect (+Allow Browsing default on). Actions: all_ops(default), read, write, key_op(needs data-transform rule), f_rd,f_wr,f_wr_app,f_cre,f_ren,f_link,f_rm,f_rd_att,f_chg_att,f_rd_sec,f_chg_sec,d_rd,d_ren,d_rd_att,d_chg_att,d_rd_sec,d_chg_sec,d_mkdir,d_rmdir (COS/IDT only f_rd,f_wr,f_rm,d_rd). LDT auto-creates read-only first rule (key_op, permit,applykey, browsing No).
- Learn Mode: denies become permit + ERROR log tagged `[LEARN MODE]`; not for IDT; a Deny rule must carry ApplyKey if Permit rule has it; don't leave on.
- Sets: names start w/ char, <=64, [A-Za-z0-9_-]. Resource set: dir relative to guard path, must end `/` (or `\`), file or `*`, Include Sub Folders (default off), HDFS toggle (Linux); wildcards only mid/end. User set: Agent or LDAP browse (max 100 shown; LDAP max entries 1-10000, default 300) or manual; vars `|uname|,|gname|` (+`|uid|,|gid|` UNIX). Process set: optional signature set; also used as RWP Trusted Process Set. Signature set signs only executables (UNIX: exec bit set; Windows: compiled exes outside GP, all files inside); error text "is invalid for the signature request" (see agent log).
- Keys: must be exportable, CTE Clients group has ReadKey+ExportKey, metadata `cte:{is_used,cte_versioned,encryption_mode CBC|CBC_CS1|XTS,persistent_on_client}`. Standard/COS: non-versioned CBC/CBC_CS1. LDT: current_key non-versioned (or `clear_key`), transformation_key VERSIONED. XTS: `xts:true`,`encryption_mode:XTS` -> extra tweak key `<name>_xts`; ARIA = CBC only. Default AES-256. Deletable default off; only CTE Admins delete CTE keys; update needs CTE Admins+Key Admins; in-use key undeletable. Unique to Client key: Persistent on Client auto, different value per client, don't use on shared FS/cluster/CIFS LDT; client option "Supports Unique to Client keys" default on (CM>=2.13), irreversible.
- Groups: `CTE Admins`, `CTE Clients` (system), `Client Admins` (reg tokens), `Key Admins`. Profile `DefaultClientProfile` auto-created (don't delete/modify).
**Transformation methods**: Copy/Restore (needs 2x storage), `dataxform` (in-place, interrupted run = discard files from logs & recopy), LDT (background, license `CTE - LiveDataTransformation` + base `CTE - TransparentEncryption`; K8s license `CTE - KubernetesProtection`). LDT states: starting, scanning, rekeying, suspended, rekeyed. LDT irreversible per client (also FHS, Confidential Computing, LDT Passive Mode). LDT on single CM: set Persistent on Client=Yes, password method Manual. No LDT decrypt/reverse on network shares. LDT Comm Group mandatory for NFS/CIFS multi-node; client in one group only; all clients of a share same group; name chars alnum . _ | -.
**Profile settings** (Transparent Encryption > Settings > Profiles; ksctl `cte profiles create --cte-profile-name X`, FAM label `"ncryptify-reserved/dsf-managed":"true"`): Log level DEBUG<INFO<WARN<ERROR(default)<FATAL (upload/file level >= log level); Duplicates SUPPRESS|ALLOW, Threshold 1-100 (5), Suppress Interval 1-1000s (600); Concise Logging (default off; secfs only; not w/ Learn Mode; msgs CGA3201I/CGA3202I); Upload: conn timeout 1-60 (59), upload timeout 1-900 (600), max interval 1-1000 (20), min 1-30 (10), msg range 100-1000 (1000), cache 200 files/100MB, drop-if-busy off; File log: on, /var/log/vormetric/vorvmd_root.log, max size 1-1000MB (1000), max old 1-100 (100), allow purge, compress. Syslog: 4 servers, formats Plain|CEF|RFC5424(default)|LEEF, UDP|TCP(default)|TLS. QoS: Rekey by Rate MB/s (default 0) or CPU cap; status check 10-1440 min (60); schedules ANYTIME/WEEKNIGHTS/WEEKENDS/CUSTOM (def 1AM-2AM Mon). RWP: Trusted Process Set, Operation Block(default)|Monitor|Disable, Alarm. MFA: OIDC connection + exempt user set (enforced for all by default). Server settings: tiers (max 20 tiers, 20 nodes total, Tier1 undeletable). Attestation: reattest 1-30 days or 1-720 h + retry. server_response_rate (0 default; 1-100 via `/v1/transparent-encryption/profiles/`).
**Clients**: states Healthy, Error (comm broken >5 min), Warning, Unregistered, Expunged (delete pending agent confirm; K8s n/a). Types FS|CTE-U; modes CTE|RWP|CTE RWP (RWP->CTE RWP irreversible); OS AIX|LINUX|WINDOWS|UNKNOWN|FREEBSD(CTE-U). Manual add: password >=8 chars w/ capital, digit, one of `! @ # $ % ^ & * ( ) { } [ ]`; Registration Allowed default off; Communication Enabled (default off manual). Status Refresh retry after 30 min. Bulk delete max 200. Unenroll blocked with active LDT GPs. Locks: Agent Lock (dirs `/<root>/agent/secfs`, `agent/vmd`), System Lock (/etc,/var,/bin; auto-enables Agent Lock; blocks msiexec/wuauclt); verify `secfsd -status lockstat`. Client settings (`|keyword|path`): `authenticator`,`authenticator_euid`,`vfsnumber`,`realfsid`,`lock`,`exempt`(6s timeout),`su_root_no_auth`,`path_no_trust`,`protect`; sig form `|authenticator+sig=<set>|/path/*`(Linux wildcard). Enable Re-sign Settings after adding processes. Encryption Key Protection: cache purge after 3 min idle. Offline: `vmsec passwd`, `vmsec challenge` (4 responses from client's Challenge Response tab). Kernel Compatibility Matrix .tgz upload (Clients>Clients>Compatibility Matrix), inherited by subdomains; incompatible kernel => Warning. Agent info collect/recollect/download (tar), unavailable behind LB. Domain Sharing: Settings>GENERAL SETTINGS.
**GuardPoints**: types Auto/Manual Directory (Manual: Linux only), Auto/Manual Raw|Block Device, Auto/Manual Cloud Storage (Linux). Max 200 paths via Enter/Browse, 1000 via CSV. Cannot guard /etc,/usr,/usr/lib,/etc/pam.d,/etc/security,/etc/vormetric,/etc/rc*,/var/log/vormetric,/opt (contains .sec), agent secfs/vmd; no nesting. RWP restricted: /proc,/usr/bin,/usr/sbin,/sbin,/bin. Windows: avoid `| ? < > : * " / ,` in paths; RWP GP = volume level (Win), dir (Linux). Options: Preserve Sparse Region (LDT, default on; once off can't return), Secure Start (Windows only; early-boot AD/SQL), Auto Mount (Linux, auto dir), Format Compatible (create-time only, irreversible, no CBC keys; Win/Linux/CTE-U NAS), MFA (per GP; client-level MFA overrides; not on client group itself). LDT on SMB/NFS needs FHS (Win, agent 7.1.0.84+). Active/passive clusters: guard active node only. Check: `df`, `secfsd -status guard`. K8s: storage group (same namespace+StorageClass; client in one group; GuardPath = `/<policyname>`), registration group; CBC-CS1 keys; quorum unsupported for K8s.
**Other**: Quorum ops (approver CTE Admins): Delete/Update{Client,ClientGroup,CSIStorageGroup,GuardPoint,Policy,PolicyElements,Profile}CTE, UpdateClient(Group)PasswordCTE; approvals set in Admin Settings>Quorum Policy. Permissions are `Create/Read/Update/Delete<X>CTE` (e.g. CreateClientCTE, ReadKeyRuleCTE, CreateLDTRuleCTE). Confidential Computing: Attestation Authority connection (admin + non-admin, Intel Trust Authority only, Azure/Google Cloud), client profile, reg token; clocks must sync. FAM Destination (TCP|TLS, DSF gateway/FQDN suffix). Load balancer: passthrough NLB only; `PATCH /v1/configs/properties/LOAD_BALANCER_ADDRESS`; profile Server Settings ignored. Reg: default Local CA "KeySecure Root CA" must be trusted by "web" interface; new Local CA needs CM service restart before registering; CA_RENEWAL needs CM>=2.14 + CTE>=7.5/CTE-U>=10.2 (not K8s). PQC: web interface group `X25519MLKEM768` (TLS1.3), else falls back secp384r1. DSM migration: CTE>=7.1, DSM>=6.4.5, target CM>=2.8, LDT agents>=7.1.1.55; Container policies not migratable.
**REST** (`/v1/transparent-encryption/`): clients, clients/{id}/resetpassword, clients/{id}/delete (force_del_client, delete_stale_clients), clients/{id}/ldtpause {paused}, clients/{id}/guardpoints {guard_paths,guard_point_params{guard_point_type directory_auto|directory_manual,policy_id,preserve_sparse_regions}}, clientgroups (+/{id}/clients; cluster_type NON-CLUSTER|HDFS), policies (+/{name}/ldtkeyrules), usersets, resourcesets, processsets, signaturesets, profiles; keys `/v1/vault/keys2/` (+/{id}/versions, /{id}/clone); web cert `PUT /v1/configs/interfaces/web/renewal-certificate`, `POST .../{interface}/renewal-certificate/apply`.
### Workflows
1. CDP Oracle: install CDP client (INGRIAN user exists) > DB Protection > + Add Database > Oracle > fill fields > Save > refresh status > User Mapping > + Add User (ING_DEFAULT_USER for default) > Tables > Add Table > Set Value per column > migrate.
2. Protect files: create key (Keys; CBC/XTS, CTE Clients ReadKey/ExportKey) > Policies>Policy Elements (user/resource/process sets) > Policies>Create Policy (type, rules, key rule) > client>GuardPoints>Create GuardPoint (path/CSV, policy).
3. Rotate LDT: `POST /v1/vault/keys2/{id}/versions` on transformation key; pause via `ldtpause`; monitor GuardPoint rekey status. Decrypt LDT GP: GET client guardpoints > GET policies/{p}/ldtkeyrules > clone/switch key to clear_key (no network shares).
4. Unlock stuck client (Linux): single-user mode > edit `secfs/.sec/conf/configuration/secfs_config` set `coreguard_locked`,`system_locked` false > multi-user. Windows: safe mode, rename `drivers\vmmgmt.sys`,`vmfiltr.sys`.
5. Offline access: client `vmsec challenge` > give challenge+hostname to admin > client>Challenge Response tab>Submit > enter 4 responses.
6. Delete stuck Expunged client: `POST /v1/transparent-encryption/clients/{id}/delete` force_del_client:true.
7. LB: Admin Settings>Properties>Load Balancer Address>Update (root domain, Application Admin).
8. Web cert renewal: upload cert (Admin Settings>Interfaces>web) then apply; CA_RENEWAL clients get LONGPOLL RenewCertificates.
### Troubleshooting
- Client Error / config not pushed / browse fails -> comm broken -> check `/var/log/vormetric/server_comms.log`, restart vmd; agents <=7.4.0 flapping on cluster node loss -> set profile server_response_rate 1-100.
- Registration conflict (name exists / stale entry) -> delete or unenroll client; else `ksctl cte clients bulk-delete --delete-stale-clients true` (API delete_stale_clients:true, no other params), retry.
- Reregistration capability errors -> capabilities can't be disabled; delete client and register again.
- Restored CM: reregistration fails -> disable LDT GPs pre-backup, UnEnroll client, reregister.
- Registration licensing failure/read-only config -> license consumed/expired (existing clients keep working).
- Log level mismatch -> check profile; client `vmsec vmdconfig`.
- Cert expired/CA changed, old agents (CTE 7.4, CTE-U 10.1, CM<=2.13) -> reregister. Logs: "Client cert updated. LONGPOLL connection is not available for client"; "Client Cert updated. Cert renewal notification are not supported for the CTE Client"; ok = "RenewCerts: Renewal has been scheduled - OK".
- Error 422 "Client has MANUAL password_creation_method. Cannot generate automatic password" -> switch to Generate/Manual first; 400 "Client is marked for deletion. Cannot modify CTE Client"; 401 "Token is expired by 50s" -> refresh token; 409 "Could not create clientgroup as it already exists"; 422 "cluster_type is a required field".
- Uninstall/delete fails with locks -> disable Agent/System Lock first; locks persist after unregister.
- Unmounted GP not recoverable -> disable GP in GUI, mount FS, enable.
- Signing: generic non-existent source error -> check agent log.
- Windows duplicate path (`C:\gp\` vs `C:\gp/\`) double-guards same folder -> corrupts files.

## CTE administration

### Reference
**Model**: CTE Agent on client (enforces policy, encrypts) + CM (keys, policies, profiles, domains). GuardPoint = path + exactly 1 policy; policy can have many GPs. Disabled GP = ungoverned (corruption risk). UI: Transparent Encryption app. CLI `ksctl cte ...`. Groups: "CTE Admins" (manage CTE; only they delete CTE keys), "CTE Clients" (registered clients; needs ReadKey+ExportKey on CTE keys), "Client Admins" (reg tokens). Perms named `<Verb><Res>CTE` (CreateClientCTE, ReadPolicyCTE, CreateKeyRuleCTE, CreateLDTRuleCTE...).
**Policy types**: Standard (access blocked during initial encrypt/rekey; keys non-versioned CBC/CBC_CS1/XTS), LDT (live, background rekey; needs add-on license; first rule auto key_op permit,applykey Browsing=No, read-only), COS (Amazon S3; CBC_CS1 only, non-versioned), IDT (Teradata/IDT devices; XTS only, 1 key rule, actions read/write/all_ops only), CTE for Kubernetes (CBC_CS1, no XTS; signature rules). Std "data transformation" toggle = offline migration policy (not for LDT/COS/IDT); then unguard, apply std policy w/ same key.
**Policy parts**: Security rules (ordered, first full match wins, firewall-style; blank criteria=All; effect mandatory), Key rules, Data Transformation rules, Signature rules (K8s only). >=1 key or security rule required. Rule criteria: Resource set, User set, Process set, Action, Effect, Allow Browsing (default on; not COS/K8s), Exclude Rule flags. Effect = Permit|Deny (default Deny) + options ApplyKey, Audit. ApplyKey rule needs >=1 key rule. f_rd_att rule must carry ApplyKey (CBC_CS1 4096B header skews sizes).
**Actions**: all_ops (default), read, write, key_op (needs DT rule; Standard/LDT), f_rd f_wr f_wr_app f_cre f_ren f_link f_rm f_rd_att f_chg_att f_rd_sec f_chg_sec d_rd d_ren d_rd_att d_chg_att d_rd_sec d_chg_sec d_mkdir d_rmdir. COS: only f_rd f_wr f_rm d_rd.
**Elements** (Policies > Policy Elements; name starts with letter, <=64 chars, [A-Za-z0-9_-]): Resource set (dir must end `/` or `\`, relative to GP path; file `*` wildcard; Include Sub Folders; HDFS toggle Linux), User set (Agent/LDAP; vars `|uname|`,`|gname|`; search shows 100; max 300 records), Process set (dir+file+optional signature set; RWP exempt resource; used as RWP Trusted Process Set: valid root, `*` only mid/end of path), Signature set (type Application|Container Image; <=200 sources/add; status Unsigned/InProgress/Finished/FinishedWithWarning/Aborted/Manual; SHA-2; Linux signs only exec-bit files; Windows signs all inside GP, only exes outside; active set cannot be deleted; K8s cannot sign: upload CSV/YAML manually). Variables: policy `never_deny`. Policy: Learn Mode (denies->permit + [LEARN MODE] ERROR log; Deny rules gain ApplyKey; N/A to IDT; not with Concise Logging), Restrict Update toggle, Clone, version counter (no rollback; use backup).
**Keys** (/v1/vault/keys2/): AES(default 256)/ARIA (ARIA=CBC only); modes CBC(default)/CBC_CS1/XTS (XTS creates `<name>_xts` tweak key; set xts:true, unexportable:false, share w/ CTE Clients read_key+export_key). meta.cte={persistent_on_client,encryption_mode,cte_versioned,is_used}. Std/COS/IDT unversioned; LDT: current_key unversioned (or clear_key), transformation_key versioned. Deletable toggle default off. Unique to Client: key-salt per client, persistent_on_client forced, never on shared/clustered/CIFS GPs; "Supports Unique to Client keys" default on from CM 2.13, irreversible. Format Compatible GP (CBC not allowed; irreversible; create-time only).
**Profiles** (Settings > Profiles; DefaultClientProfile auto-created, don't edit/delete; `ksctl cte profiles create --cte-profile-name X --labels ...`; FAM label `"ncryptify-reserved/dsf-managed":"true"`): Log level DEBUG<INFO<WARN<ERROR(default)<FATAL; upload/file/syslog level must be >= base level; Duplicates SUPPRESS thr 5 (1-100) interval 600s (1-1000); Concise Logging off (secfs only; msgs CGA3201I/CGA3202I); upload: conn timeout 59s, upload timeout 600s, max int 20s, min int 10s, msg range 1000 (100-1000), cache 200 files/100MB; file: /var/log/vormetric/vorvmd_root.log, max 1000MB, 100 old files, Compress, Allow Purge; Syslog <=4 servers, default TCP, RFC5424 (also Plain/CEF/LEEF), TLS needs CA/cert/key; QoS: rekey by rate MB/s (default 0) or CPU cap, status check 10-1440 min (60), schedules ANYTIME/WEEKNIGHTS/WEEKENDS/CUSTOM; RWP: trusted process set, op Block(default)/Monitor/Disable, alarm; MFA: OIDC connection + exempted user set; Server settings: node tiers (<=20), unavailable behind LB; Attestation reattest 1-30d/1-720h.
**Clients**: states Healthy, Error (comm broken >5 min), Warning, Unregistered, Expunged (delete pending agent confirm; not for K8s). Types FS/CTE-U; modes CTE/RWP/CTE RWP (RWP->CTE RWP irreversible); OS AIX/LINUX/WINDOWS/FREEBSD(CTE-U). Manual add: reg allowed default off; K8s can't be manual. Refresh (status) limited 1/30 min. Delete: max 200 bulk; force `POST /v1/transparent-encryption/clients/{id}/delete` {"force_del_client":true}. Cannot unenroll w/ active LDT GP. LDT enable irreversible (unregister+delete to reclaim license); LDT Passive Mode irreversible, no CBC; Confidential Computing irreversible; FHS (Windows SMB). Password >=8 chars w/ upper, digit, special; Generate(default dynamic)/Manual(static); offline: `vmsec passwd`, `vmsec challenge` -> 4-part response (client Challenge Response tab). Encryption Key Protection: cache keys evicted after 3 min idle. Single-CM LDT: set Persistent on Client + manual password.
**Locks** (Settings > SECURITY SETTINGS; default off): Agent Lock protects agent/secfs & agent/vmd; System Lock protects /etc,/usr,/var etc and auto-enables Agent Lock; verify `secfsd -status lockstat`; disable before agent uninstall/client delete/OS patching.
**Client settings** (Settings tab, lines `|keyword|/path`): authenticator, authenticator_euid (oracle/DB2 launchers), su_root_no_auth, path_no_trust, trust, protect, vfsnumber/realfsid (AIX), Windows lock/exempt (6s timeout). `+sig=<sigset>` form, `*` Linux only. Toggle Re-sign Settings after adding processes or new entry ignored. Linux defaults: sshd, in.rlogind, login, gdm-binary, kdm, vsftpd(euid), sshd-session. Never tag su as authenticator. Cron unsupported. Inherit from client group (not for unregistered clients; password not inherited; editing client breaks inheritance).
**Groups**: Client groups NON-CLUSTER|HDFS (cluster type immutable; HDFS membership exclusive); desc <=256; Designated Primary Set. LDT Communication Group: required for LDT over NFS/CIFS multi-node; 1 per client; all clients on a share same group; register by hostname/IP; name [A-Za-z0-9._|-]; Windows "LDT Access Only" clients excluded. K8s: client name `<node>_<storageclass>_<ns>_<rand>`; Storage group (ns+StorageClass; GuardPolicy type csi_manual, GuardPath=`/<policyname>`) ; Registration group (COS GPs). Client can be in 1 storage group.
**GuardPoint types**: Auto/Manual Directory (manual: Linux only, `secfsd -guard|-unguard`), Auto/Manual Raw/Block Device, Manual Cloud Storage, Ransomware Protection Only (no policy; Windows=volume, Linux=dir), IDT. Limits: 200 paths via browse, 1000 per CSV, 200 GPs bulk remove. Restricted Linux: /proc /usr /opt /tmp /bin /sbin /lib /lib64 /etc/* pam/security/systemd, install dir; Windows: C:\Windows, Program Files(x86), ProgramData, Users. No nesting/overlap; path delims not `| ? < > : * " / ,`. Preserve Sparse Region default on (LDT); Secure Start Windows only (not manual clients); MFA per GP only if client-level off; client-group GPs MFA OK. LDT SMB/NFS: Auto Directory only, mount NFS first, one path type. GP via API: `POST /v1/transparent-encryption/clients/{id}/guardpoints` {guard_paths,guard_point_params:{guard_point_type:directory_auto|directory_manual|rawdevice_auto, policy_id, preserve_sparse_regions, early_access, cifs_enabled, network_share_credentials_id, is_idt_capable_device}}.
**Other APIs**: policies `/v1/transparent-encryption/policies` (policy_type Standard|LDT|Cloud_Object_Storage|IDT; key_rules/ldt_key_rules/idt_key_rules); usersets, resourcesets, signaturesets, processsets, profiles, clientgroups, `clients/{id}/resetpassword`, `clients/{id}/ldtpause` {paused}, `policies/{p}/ldtkeyrules`, key rotate `/v1/vault/keys2/{id}/versions`, clone `/keys2/{k}/clone`; reg stale cleanup `clients/delete`. LB property `PATCH /v1/configs/properties/LOAD_BALANCER_ADDRESS`. Web cert renewal `PUT/GET /v1/configs/interfaces/web/renewal-certificate`, `POST .../{interface}/renewal-certificate/apply`.
**Comms/misc**: Agent long-polls every CM node (3 min hold); LB must be passthrough NLB (profile server settings & Agent Info unavailable). Default Local CA CN "KeySecure Root CA" must be trusted by web interface. CA_RENEWAL (CM>=2.14, CTE>=7.5, CTE-U>=10.2; not K8s). Client certs auto-renew 60d before expiry (daily retry). Quorum ops (approver CTE Admins): Delete/Update ClientCTE/ClientGroupCTE/GuardPointCTE/PolicyCTE/PolicyElementsCTE/ProfileCTE, CSIStorageGroupCTE, Update*PasswordCTE; not K8s clients. PQC: X25519MLKEM768 (TLS1.3; else falls back secp384r1). Reports: Clients Health/Keys/Profiles/Policies, Policies Keys, GuardPoints, Clients GuardPoint Status (PDF/CSV). Licenses: CTE - TransparentEncryption, CTE - LiveDataTransformation, CTE - KubernetesProtection, RWP. Splunk 7/8 via syslog RFC5424 (TLS preferred), sourcetype rfc5424_syslog.
**Backup/Migrate**: policy backup excludes keys (unless backed up together) and signatures (re-sign after restore); same-name policies skipped; restore keys first. DSM->CM: DSM>=6.4.5, CTE>=7.1, CM>=2.8, LDT agent>=7.1.1.55; `ksctl migrations apply import --auto-cte-groups`; no nested GPs; reregister w/ identical case-sensitive client name; unguard LDT first; container policies not migratable; profiles named `profile_<dsm-host>_<domain-id>`.

### Workflows
**Protect a path**: 1 Create key (Keys; CTE props, exportable, CTE Clients read/export) 2 Create elements 3 Policies > Create Policy (type, security rules, key rules) 4 Clients > client > GuardPoints > Create GuardPoint (policy, type, path) 5 check status (Unknown until client reports).
**Register client**: create reg token (tied to client mgmt profile/CA; restart CM services if token uses newly created Local CA) -> run agent installer/`register_host` w/ token. Or Clients > Create Client (manual). Reregister: new token + same capabilities + group name(s).
**External CA registration**: CA > External > Add External CA; Admin Settings > Interfaces > web > Edit > External Trusted CAs; restart web (Admin Settings > Services); token with that CA; agent files client_cert.pem, client_key.pem, passphrase in dir; `export EXTERNAL_CERT_DIR=/root/cert_files`; `register_host` (Win `register_host.exe -extcertdir=c:\temp\cert_files`); renew `vmutil -a vmd -d <dir> updatecerts` (same CN required). Local CA renew: `vmutil -a vmd renewcerts`.
**Sign signature set**: Policy Elements > Signature Sets > set > Source tab > Select Client > Sign icon; check status; re-sign after file changes/rekey.
**Enable LDT**: client > Settings > Live Data Transformation > Apply; LDT policy (unversioned current_key or clear_key + versioned transformation_key); LDT GP; pause/resume via ldtpause; rotate key = new key version.
**Decrypt LDT GP (API)**: get guardpoints -> get ldtkeyrules -> clone key unversioned -> create new LDT policy (current=clone, transformation=clear_key) -> unguard old GP -> client `voradmin ldt attr delete <GP>` -> new GP -> wait rstatus "Rekeyed" -> unguard. Not for network shares.
**Web cert renewal**: PUT renewal-certificate -> wait for "Sending pending event to CTE client" per client + ~24h -> apply -> restart web service.
**Kubernetes**: create storage group (ns+StorageClass) -> attach GuardPolicy (CTE for Kubernetes policy) -> register K8s client; client cannot register until GuardPolicy exists. Unenroll before deleting pod. Error clients deletable (force_del_client).
**Unlock Linux manually**: single-user mode, secfs/.sec/conf/configuration/secfs_config set coreguard_locked & system_locked false. Windows: safe mode, rename drivers\vmmgmt.sys and vmfiltr.sys.
**Teradata**: `voradmin idt config -external xform /dev/sdb`, then IDT GP.
**Agent info**: client > Settings > Collect/Recollect/Download Agent Information (tar; 80% volume prompt to clean).
**Backup policies**: domain backup key -> download -> backup (keys+policies) -> scp -> upload key, upload backup -> restore -> verify; separate: restore keys before policies.

### Troubleshooting
- Client Error / config not pushed / browse fails -> comms; read /var/log/vormetric/server_comms.log, restart vmd. Agent <=7.4.0 after CM node down -> set profile `server_response_rate` 1-100 (default 0) via /v1/transparent-encryption/profiles.
- Registration conflict -> client name exists; delete/unenroll, or stale entry: `ksctl cte clients bulk-delete --delete-stale-clients true` (API clients/delete delete_stale_clients=true, no other params), retry.
- Reregister capability errors -> capabilities cannot be disabled on rereg; delete client, register without them.
- Licensing errors/LDT unavailable/read-only -> base/LDT/K8s license consumed or expired; existing clients keep working, new ones cannot register.
- After CM restore on new appliance rereg odd -> stop LDT GPs before backup, restore, UnEnroll client, reregister.
- Client stuck Expunged -> force delete API force_del_client:true.
- Uninstall/delete fails with locks -> disable Agent/System Lock first; if client already unregistered, manual unlock (above).
- "User Not Authenticated" [CGP2602E] -> authenticator missing/wrong path or login before CTE start; fix client settings, relogin, `secfsd -status auth`. "FAKED USER!! DENIED" -> setuid su impersonation, not authenticated.
- New process ignored in client settings -> toggle Re-sign Settings.
- Signature set FinishedWithWarning / "is invalid for the signature request" / VMD3824W -> missing file or permission; check vorvmd_root.log (Win vorvmd.log); error codes 1 not exist,3 invalid arg,6 no space,10 permission denied.
- Policy denies after enabling Learn Mode off -> review [LEARN MODE] logs first; Deny+ApplyKey needed to avoid corruption.
- Clients fail after web cert change -> clients not yet notified; log "Client cert updated. LONGPOLL connection is not available for client" (inactive) / "Cert renewal notification are not supported for the CTE Client" (no CA_RENEWAL); fix: Get Capability (Settings > Client Information and Capabilities) or reboot agent; `Failed to notify the CTE client` -> restart web service; run `vmutil -a vmd renewcerts`; else reregister.
- Unmounted manual/auto GP after lock -> disable GP in GUI, mount fs, enable GP.
- Conn lost after reboot w/ unique-to-client keys -> app hangs until `vmsec passwd`/`vmsec challenge`.
- Mismatched log levels -> check profile; `vmsec vmdconfig` on client.
- DSM migration: new client has no config -> client name case mismatch; GP create errors only in audit records, verify via reports.
- Corruption on shared storage -> clients of one share not in same LDT comm group, or unique-to-client key used.
