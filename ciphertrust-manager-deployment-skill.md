## Deployment

### Reference
- Doc basis: CipherTrust Manager (CM) v2.25. Product names: k170v (<=4 CPUs, license-based; lab/KMIP/low TPS) and k470v (>4 CPUs) = virtual; k470/k570 = physical (k570 has embedded Luna PCIe HSM; k470 none); k160 = TCT appliance, 2.25 NOT supported (ships 2.23). Models: 4x1G or 2x1G+2x10G(SFP, eth0/1). KeySecure Classic (k450/k460) data can migrate to k470/k570.
- Images: AWS=AMI via Thales Support Portal provisioning (Tools > Provisioning Requests); GCP=shared custom image (project `gemalto-supporteng`, via support ticket; 2.25.0 NOT in GCP Marketplace); Azure=BYOL Marketplace (latest only, Community Edition; back to 2.6 via `az`); Oracle=QCOW2 import from Object Storage URL; Alibaba=custom image; VMware=OVA (vSphere/ESXi>=5.1; <=5.0 change hw version vmx-09 to vmx-08/07 w/ OVF Tool); Hyper-V=VHDX (Generation 1 only); Nutanix AHV=OVA->decompress->VMDK (mandatory); OpenStack/KVM/QEMU/OpenShift/Proxmox=qcow2; HPE Morpheus VME=OVA (tested 8.0.10, OS ubuntu 24.04 64bit, min mem 16GB); Azure Local / Azure Stack Hub=VHDX.
- Min virtual sizing (all platforms): 300 GB system volume (holds data+backups), 16 GB RAM, vCPU 2 standalone / 4 clustered, 1 NIC. (Alibaba wizard text says min 100 GB storage.) Community Edition (trial mode) limited to 4 processors; k470 license for more. Launches in Community Edition; 90-day trial for full function (see Licensing). GCP default machine e2-standard-4. OpenShift tested 4.18.0 + OpenShift Virtualization, template "Red Hat Enterprise Linux 8 VM". Nutanix: bus SCSI, Legacy BIOS. Hyper-V min startup mem rec 4 GB, 4 procs.
- GCP security options (2.25+): Confidential Computing (AMD SEV, SEV-SNP, Intel TDX), Secure Boot, vTPM, Integrity monitoring. Supported combos (CC/SecureBoot/vTPM/IntMon): E/D/E/E, E/E/E/E, D/E/E/E, D/D/E/E, D/D/D/D. For 2.22-2.24 data: launch new 2.25 and backup/restore.
- Ports (TCP unless noted): 443 in (Web UI/ksctl/REST/CTE/CTE-U/DPG/CRDP/CT-V/CT-VL/CADP-Java WS; 9443 in on AWS China); 80 in; 22 in (SSH ksadmin); 5696 in (KMIP); 9000 in (NAE); 5432 in/out + 2380 in/out (cluster); 11117 in (DDC agent); 161 UDP in/162 UDP out (SNMP); 53 UDP out (DNS); 123 UDP out (NTP); 389 out (LDAP), 636 out (LDAPS); 587 out (SMTP); 514 UDP out + 6514 TCP out (syslog); 22 out (SCP backup; also Luna NW HSM/T-Series/CloudHSM); 1792 out (Luna NTLS; also temp during STC setup), 5656 out (Luna STC); 2223-2225 in/out (AWS CloudHSM, attach cluster SG on EC2); 443 out (DPoD Luna Cloud HSM); 8443 out (TDP Knox for DDC). Port 9100 reserved internal. Add SG rule for every new interface. Akeyless gateway (Secrets Mgmt) needs public egress to Akeyless SaaS (not covered here). Restrict cluster port 5432 via cluster allowlist.
- TLS (setting `minimum_tls_version`): Web UI min TLS1.2 max 1.3 (default 1.2); NAE and KMIP supported 1.0-1.3, default min 1.2. TLS1.0/1.1 to be removed. Always enable TLS on NAE in production.
- Identities: `ksadmin` = OS/system admin (SSH key only, RSA OpenSSH pubkey; private key OpenSSH/PKCS1/PKCS8; RSA4096 rec, 2048 min; Azure username MUST be ksadmin; GCP tool-supplied key user = `ubuntu`). `admin`/`admin` = initial Application Admin, forced change at first login. Password policy default: min len 8, max 30, >=1 upper/lower/digit/other. No ksadmin session timeout by default: append `TMOUT=<sec>` to /home/ksadmin/.bashrc then `source` it.
- Cloud-init (user-data YAML, spaces only; AWS limit 16 KB else ignored; only AWS/Azure/Oracle/private cloud/Alibaba user-data):
  `keysecure: initial-user: generate-password: true` (pw in /var/keysecure/password/out); `keysecure: default-ca:` / `default-server-cert:` with CN (only required; else section ignored), emails, names[C,ST,L,O,OU], dns-names, ip-addresses (only `emails` honored as SAN per note); `keysecure: netcfg: config_ipv6: dhcp` (default `auto`; set before first boot; avoid dhcp on AWS w/o IPv6 = 5 min boot delay); static IP `keysecure: netcfg: iface: {name,type: static,address,netmask,gateway,dns1,dns2}` first boot only; disk enc `diskenc: encrypt: true` (+ `ssh_authorized_keys:` list for private cloud; public clouds already have key); HSM `keysecure: hsm: {type: luna|aws|dpod, conninfo: '{"partition_name":..,"partition_password":..}', config:{host,server-cert,client-cert,client-cert-key}}` - NOT recommended (secrets visible in console); use HSM API instead.
  First NIC names: Alibaba ens5, AWS ens5, GCP ens4, Azure eth0, Oracle ens3, vSphere ens32.
- Disk encryption: always on once enabled, cannot be disabled; unlock each boot with `ksctl diskenc secureboot -i <ssh_privkey>` (PEM key; OpenSSH-format private key NOT supported; may add `-u https://<host>` ). Check `ksctl diskenc status -p`. Best practice: encrypt at first launch (secrets generated first boot); upload externally signed cert to preboot interface (not possible via cloud-init). Disk resize impossible if unencrypted AND cloud-init disabled -> encrypt first or backup/restore to new VM.
- Root-of-trust HSM: if configured, all secrets protected by non-exportable HSM key; CM must connect to HSM on first boot. Needs partition+password+client cert prepared by HSM admin. Restore RoT keys from Backup HSM BEFORE configuring RoT. Reset methods do not reset HSM.
- ksctl: download via UI API/"CLI Guide" > ksctl_images.zip (ksctl-linux-amd64, -darwin-amd64, -win-amd64.exe). Config ~/.ksctl/config.yaml (%HOMEPATH%\.ksctl): KSCTL_USERNAME, KSCTL_PASSWORD, KSCTL_URL, KSCTL_NOSSLVERIFY(default false), KSCTL_CONNECTION, KSCTL_TRUSTED_CA_FILE, KSCTL_SERVER_NAME, KSCTL_VERBOSITY, KSCTL_JWT, KSCTL_RESPFMT, KSCTL_TIMEOUT (default 30s), KSCTL_AUTH_DOMAIN. Flags override (--user --password --url --connection --nosslverify --trusted-ca-file --server-name --verbose --jwt --respfmt --timeout --domain). Precedence: CLI args > config file passed on CLI > env vars > default config file. `ksctl login --user/--domain`. Run from remote host, not on CM.
- Physical k470/k570: 1U 19", 16 GB RAM, 1x2TB SATA, 4-core CPU, no IPMI, 2 PSUs (use independent sources), op temp 0-35C, tamper seals. Serial 19200 8N1 (Prolific PL2303 USB-RJ45 adapter; pins TxD/RxD 3,6; no handshake). Eth0 DHCP by default; eth0+eth1 or eth2+eth3 bondable. Prereqs: CM firmware 2.0+; k570 PED model needs PED + 3 PED keys (blue/red/black). Front locking bezel optional. Red Decommission button (rear, recessed, works unpowered) deletes all HSM partitions/contents irreversibly (k570).
- NTP: needed for HSM RoT, clustering, Connection Manager, OIDC/LDAP, connectors, cloud integrations. Algos MD5, SHA-1, SHA-256 (default), SHA-384, SHA-512.
- SSH key replace (one-time via ksctl/API; more keys can be added later): needed on physical/private-cloud first boot; public-cloud launch key does not need replacing.
- Reset methods: REST/CLI reset (admin; keeps OS cfg, SSH keys, disk enc, network, version); `kscfg system reset [-f] [-y]` (ksadmin; same preservation; needs host-daemon); `kscfg system factory-reset [-y]` (k470/k570/k160 MkII; wipes network+OS cfg, reverts to factory firmware, 2 reboots, up to 15 min; fallback `sudo /opt/keysecure/ks_reset_to_factory.sh`); zero-knowledge factory reset (k470/k570, serial only); k160 zeroization buttons. Reset changes Connector Lock Code: old connector licenses invalid; rejoin cluster to resync or ask Thales to reissue.
### Workflows
1. Generic virtual first boot: launch image (>=300GB/16GB/2-4 vCPU) w/ SG ports above -> (private cloud) console `ksadmin` login at `ciphertrust login:` (Ctrl+C shows IP; Enter refreshes) -> browse https://<ip> -> paste SSH pubkey (replace default; error screen is normal) -> login admin/admin -> set new password -> add NTP (Admin Settings > NTP > +Add NTP Server, or `ksctl ntp servers add --host <h> [--key <k> --key-type <alg>]`) -> license (Licensing).
2. AWS: request provisioning (Support Portal > Tools > Provisioning Requests > Create; product CipherTrust Manager, version, region, AWS acct, optional extra regions; email "Cloud Provisioning Request Complete"; copy AMI ID) -> EC2 Launch Instance > My AMIs -> type meets min -> key pair (RSA) -> VPC/subnet, Auto-assign Public IP Enabled, SG with 22 + 443 -> storage >=300 GiB -> Advanced > User data (cloud-init file, <=16KB; CLI `--user-data file://config.dat`) -> SSH as `ksadmin@<public DNS>` (PuTTY: prefix ksadmin@, Connection>SSH>Auth key) -> GUI.
3. AWS China (443 not reachable): launch helper EC2 in same VPC with ksctl; config.yaml KSCTL_URL=https://<privIP>:443, NOSSLVERIFY true; `ksctl changepw --new-pw X --confirm-pw X <config.yaml>`; `ksctl interfaces modify --name web --port 9443`; browse https://<pubip>:9443.
4. GCP: support ticket (Google Group email, image version, project ID) -> confirm -> Compute Engine > VM instances > Create; boot disk > Custom images > source project `gemalto-supporteng`; 300GB std PD; allow HTTP+HTTPS; optional Security (Confidential VM/Shielded; re-check boot disk after enabling) -> open External IP, paste ksadmin SSH key in UI -> admin login -> NTP -> disable cloud-init: get ks_patch_disable_cloud_init.tar.gz.gpg (KB0029319), `scp -i key file ksadmin@ip:.` (Windows `pscp`, PPK), then `sudo /opt/keysecure/ks_upgrade.sh -f <archive>`.
5. Azure Marketplace: Create VM, size meets min, auth SSH public key, username `ksadmin`, OS disk Standard HDD, Custom Data = cloud-init, allow 443. Gov regions: USGov Arizona/Iowa/Virginia/Texas. Older (>=2.6) via CLI: `az vm image list --offer cm_k170v --all` -> `az vm image terms accept --urn <urn>` -> `az vm create --resource-group R --name N --image <urn> --size Standard_F4s_v2 --admin-username ksadmin --generate-ssh-keys|--ssh-key-name X|--ssh-key-value F [--custom-data config.dat] --public-ip-sku Standard` (publisher thalesdiscplusainc1596561677238, sku ciphertrust_manager); open 443.
6. Azure Dedicated HSM RoT: same RG for CM, Luna client Windows VM, HSM; vnet with Compute + HSM subnet (delegate to Microsoft.HardwareSecurityModules/dedicatedHSMs) + gateway; deploy via `New-AzResourceGroupDeployment -ResourceGroupName R -TemplateFile Deploy-1HSM-toVNET-Template-v1.1.json -TemplateParameterFile ...Params-v1.1.json -Name HSMdeploy -Verbose` (~30 min); HSM login `tenantadmin` (hsm init, partition create); Luna client 7.2: `scp tenantadmin@<hsm>:server.pem .`, `./vtl createcert -n <CM_IP> -d 10 -v`, copy client.pem, lunash `client register -client N -ip <CM_IP>`, `client assignPartition -client N -partition P`, `client show -c N`; CM UI System > HSMs > "SafeNet Luna SA 5, 6, or 7 - Network HSM" (label, CO password, serial, IP, server cert, client cert+key); server restarts; re-login.
7. Oracle: support gives Object Storage URL -> Compute > Custom Images > Import Image (OS Ubuntu, QCOW2, Paravirtualized) -> wait Succeeded/100% -> Create Instance (leave boot volume/live migration defaults) -> add SSH key; cloud-init under Advanced > Management.
8. vSphere: Deploy OVF Template (if error, `ovftool.exe --lax src.ova dst.ovf`); static IP via cloud-init: add CD drive, vApp Options > OVF Environment Transport=ISO Image, Properties: key/label `user-data` default value = base64 (`openssl base64 -in f -out o`) of YAML. Hyper-V: unzip VHDX, New VM Gen 1, existing disk; cloud-init via ISO: `genisoimage -o config.iso -volid cidata -joliet -rock user-data meta-data` (meta-data `instance-id: x`). KVM: `virt-install ... --disk path=img.qcow2,size=16,format=qcow2 --disk path=config.iso --import`.
9. OpenShift: Virtualization > VirtualMachines > Create from template (RHEL 8) > disk source Upload qcow2 > Quick create; then Service type NodePort (port/targetPort 443, nodePort 30000-32767, selector kubevirt.io/domain=<vm>) and Route (host, TLS passthrough) to expose 443.
10. Proxmox: verify `egrep -c '(vmx|svm)' /proc/cpuinfo` >0 and `ls /dev/kvm`; `qm create 9100 --name N --memory 16384 --cores 2 --sockets 1 --net0 virtio,bridge=vmbr0 --scsihw virtio-scsi-pci`; `qm importdisk 9100 <img>.qcow2 local-lvm`; `qm set 9100 --scsi0 local-lvm:vm-9100-disk-0`; `qm set 9100 --boot order=scsi0`; REQUIRED `qm set 9100 --rng0 source=/dev/urandom,max_bytes=1024,period=1000`; cloud-init: `pvesm set local --content iso,vztmpl,backup,snippets`, file in /var/lib/vz/snippets, `qm set 9100 --ide2 local-lvm:cloudinit`, `qm set 9100 --cicustom "user=local:snippets/cm-user-data.yaml"`.
11. Encrypt disk after deploy / unlock: `ksctl diskenc status -p`; `ksctl diskenc secureboot -i <key>`. Recommended order: cloud-init encrypt -> launch -> upload external cert to preboot -> reboot -> verify cert while unlocking.
12. Resize disk: shut down -> resize via provider (AWS Modify Volume; vSphere Edit Settings; result within 2 GB smaller) -> power on -> `ksctl diskenc secureboot -i <key> -u https://<dns>` if encrypted -> `df -h /` as ksadmin.
13. Replace default SSH key: `ksctl services status` (status "bootstrap") -> `ksctl ssh keys add -k "<pubkey>"` -> status "started". API: GET /system/services/status; POST /system/ssh/keys {"key":"..."} (no auth needed). Pre-service access uses a hard-coded default key (not for production).
14. Initial password: GUI forced change; CLI `ksctl changepw --url=https://<h> --user admin --password <cur> --new-pw N --confirm-pw N`. Autogenerated: `ssh ksadmin@<addr> cat /var/keysecure/password/out` or `ksctl init getpw --url https://<ip> --identityFile <key> --user admin`; change immediately.
15. k470/k570 install: verify tamper-evident bags/labels vs advance shipping notice; rack; cable power(2 sources)+network (+PED USB for PED k570); press Start; serial 19200 8N1 -> `ksadmin` login/create password (Ctrl+C shows DHCP IP) -> GUI paste SSH key (PEM RSA) -> admin pw change -> NTP -> optional bezel. Static IP etc via nmcli.
16. k570 local HSM (run `/usr/safenet/lunaclient/bin/lunacm` as ksadmin; Model Luna K7=Thales; Luna-T7=TCT). Thales K7: `slot list`/`slot set -slot N` (Admin Token Slot) -> `hsm factoryReset` -> `hsm init -label L` -> `role login -n so` -> optional FIPS `hsm changehsmpolicy -policy 12 -value 0` (destructive; decide now) -> `partition create` -> `slot set` user slot -> `partition init -label P` -> PED: `partition changepolicy -policy 22 -value 1` and `-policy 23 -value 1` (auto-activate; cache lasts 2 h after power loss) -> `role init -name Crypto Officer` -> `role login -name Crypto Officer` -> `role changePw -name Crypto Officer` (initial cred valid once). TCT T7 password: `hsm init -initwithpwd -label L -password SOPW -domain D` -> `hsm login -password` -> policy 12 optional -> `partition create -password PP -domain D`. TCT PED: `hsm init -initwithped -label L` (blue SO, red domain) -> `hsm login` -> `partition create` (black owner, red) -> `partition login` -> `partition createChallenge` (note login secret) -> policy 22 then 23. Then configure RoT: CM HSM setup API / `ksctl hsm setup` with partition label + challenge/password.
17. Remote PED (k570): `ped vector -init` (orange key) -> remote workstation Luna Client>=7.0.1 `PedServer -m start`, check `pedserver -mode show` (Server Port 1503, Admin 1502) -> on k570 `ped connect -ip <ws_ip> -port 1503` -> `role login -n so` (Thales K7) / `hsm login` (TCT).
18. Secure transport k570 (STM): `sudo systemctl stop keysecure` -> lunacm; PED: deactivate CO (`slot set` user slot, `role login -n po`, `role deactivate -n Crypto Officer`) else verification-string mismatch -> backup HSM -> `slot set` admin slot -> `role login -n so` -> `stm transport` ('proceed') -> record Verification + Random User strings (send separately from device) -> power off. Recover at destination: lunacm, `slot set` admin slot, (`ped connect`), `role login -n so`, then STM recover with the two strings; no ksadmin pw/HSM reconfig needed.
19. Backup/restore RoT keys via Luna Backup HSM (k570): needs Luna Client >=10.4.0; target must have NO RoT keys (new k570: init partition only, do NOT set up RoT; existing: system backup w/o "tied to HSM", system reset, `lunacm` CO login, `partition clear`, `partition contents`); workstation runs `rbs s -port 1792`; on k570 `./vtl addserver -n <ws_ip> -c <server.pem>`, `./vtl listservers`.
20. nmcli (ksadmin; physical + private cloud; use provider tools on public cloud; never touch `kylo0`; avoid over-SSH edits): `nmcli device`, `nmcli device show X`, `nmcli conn`; bind by MAC: `nmcli conn add type ethernet con-name N ifname '' -- ethernet.mac-address MAC ipv4.method auto ipv6.method ignore`; static: `nmcli conn modify N ipv4.method manual ipv4.addresses A/P ipv4.gateway G ipv4.dns D1,D2`; `ipv4.ignore-auto-dns yes`; apply `nmcli conn up N`. Disable IPv6: `ipv6.method ignore` (link-local stays). Static route: `nmcli conn modify N +ipv4.routes "net gw"`; no default route: `nmcli c mod eth1 ipv4.never-default true ipv6.never-default true`; verify `ip route`. Bond: `nmcli conn add type bond con-name bond0 ifname bond0 -- bond.options mode=active-backup[,fail_over_mac=1]`; slaves `nmcli conn add type ethernet con-name ens3-bond0 ifname ens3 master bond0` (delete old profile first); set `802-3-ethernet.cloned-mac-address` for stable MAC (use fail_over_mac=0 then). Bind each slave (not bond) to MAC. VLAN: sub-ifaces e.g. ens3.10; keep subnets/routes distinct.
21. Resets: API `POST /v1/system/services/reset` (optional "delay", default 5s) / `ksctl services reset [--delay]`; before kscfg reset: DB backup + download all backup keys. Zero-knowledge: serial console, login `factoryreset` -> 1 generate challenge, send to Thales, 2 paste response, type `proceed` (ksadmin can disable challenge, do right after deploy).
22. Emergency/HSM tamper clear (Thales k570): lunacm admin slot; `hsm tampershow` (error "Driver command failed: Input/output error / Failed to display tampers error=5"); `hsm restart` (replug PED USB); `hsm tampershow`; `role login -name so`; `hsm tamperclear`; PED re-auth with black key.
### Troubleshooting
- Web UI shows error on first browse / services not started -> default SSH key not replaced (status "bootstrap": "The SSH public key for the ksadmin user must be replaced before the ${cm} will be functional") -> paste key in UI or `ksctl ssh keys add`. One-time only via ksctl.
- admin/admin rejected -> initial pw auto-generated via cloud-init -> read /var/keysecure/password/out.
- Console shows no/stale IP on first boot -> press Enter or type user + Ctrl+C; no DHCP and no cloud-init -> use nmcli static.
- vSphere OVA import error (compressed disk) -> `ovftool.exe --lax` to uncompressed OVF; Nutanix needs VMDK extracted first.
- AWS cloud-init ignored -> user-data >16KB (strip whitespace/comments; DPoD config often too big). 5-minute boot delay -> `config_ipv6: dhcp` without IPv6 interface.
- AWS China GUI unreachable on 443 -> change web port to 9443 via ksctl from in-VPC host.
- GCP distribution project/image not visible -> no ticket confirmation, wrong Google account/group, IAM propagation delay; enabling Confidential VM may clear boot disk -> reselect. Static IP verify with nmcli.
- Disk resize unavailable -> unencrypted + cloud-init disabled -> encrypt (before disabling cloud-init) or backup/restore to new VM.
- Boot paused after resize/reboot on encrypted VM -> run `ksctl diskenc secureboot` (PEM key; OpenSSH private key rejected). `ksctl diskenc status` may time out during restart -> watch console.
- Proxmox boot hangs, no VM traffic -> no virtual RNG -> add `--rng0`. Static IP set but "Destination Host Unreachable" -> vmbr0 has `bridge-ports none` -> bridge physical NIC (iface ens33 inet manual; vmbr0 dhcp, bridge-ports ens33), `ifreload -a`; restore .bak if IP not back in ~20s. Nested virt: expose HW virtualization in ESXi and full power-cycle.
- Interface MAC/name swap after reboot (upgraded from <=2.4, eth*/bond) -> bind connections to MAC; bonds not persisting -> delete duplicate profile or raise priority; ping/UI fail after IP change -> check gateway/DNS, use serial.
- k570 `CKR_Timeout` during multi-key PED imprint -> ask support to raise PED timeout via Support CLI. `CKR_PIN_EXPIRED` -> Crypto Officer initial credential not changed with `role changepw`.
- k570 services fail ~2 h after power loss (PED) -> cached creds expired -> reboot, replug PED USB, authenticate black key; enable policies 22/23 or remote PED.
- "HSM Offline" alarm within 30 s = tamper (lid removed); CM auto-restarts after 5 min HSM loss; services stay down until tamper cleared (workflow 22). Configuring RoT then restoring RoT keys -> app unavailable after reboot, needs support.
- Serial: Windows 10 PL2303 driver crash -> use other OS; blank screen -> press Enter; don't plug serial cable into Ethernet port.
- After system reset connector licenses fail -> Connector Lock Code changed -> rejoin cluster or reissue licenses.
- Pointer: Secrets Management (Akeyless) and DDC deployment/ports: see their own docs.

## Licensing, migration, release notes

### Reference
**Licensing basics (EMS / Sentinel License Portal; CM v2.25 docs)**
- Physical k470/k570 ship licensed. Virtual CM (k170v <=4 CPUs; k470v >4 CPUs) starts as **Community Edition** (no VCM license; no connector licenses). 90-day trial or purchased license unlocks all. Newest applied k170v/k470v license overrides older. Exceeding CPUs on k170v: login warning + alarm (clear only by reducing CPUs).
- Licenses node-locked: each cluster node + each clone needs own VCM license (not replicated). Snapshot restore needs no new license; full redeploy needs support-assisted revoke.
- Two lock codes (Admin Settings > Licensing > Lock codes tab): **Key Manager Lock Code** (per node -> VCM license; feature `Virtual_KeySecure`) vs **Connector Lock Code** (cluster-wide, replicates to all nodes -> connector + KMIP licenses). Wrong lock code => upload error. Portal limits license-string generation; license string for one CM unusable on another. License file in download zip: `lservrc`.
- Community Ed. blocks NEW: child domains, clustering, new LDAP/OIDC connection, HSM root of trust, backup/key-rotation schedules. Existing resources keep working after expiry/delete/trial stop; backups restore licensed resources into CE; CE node cannot join cluster (licensed node later in CE stays in cluster).
- Upgrade/downgrade keeps licenses+expiry; CE upgrade/downgrade => CE (>=2.8 shows Community Edition). Reset: CE wipes data; licensed/trial reset removes connector licenses, keeps VCM license + original expiry.
- Flex bundles: Basic (CAKM Oracle TDE/MSSQL EKM/LUKS, CTE, CTE-U), Advanced (CADP, CRDP, CT-VL, CTE-K8s, CT-V, DPG), Premium (BDT, CDP, CTP, CTE SAP HANA, CTE Teradata), Utilities (LDT, Confidential Computing, CTE Ransomware), Ability (KMIP). Redeemable/tradeable within a type. Portal "Variant" picks connector (e.g. ProtectDB=CDP, VaultedTokenization, VaultlessTokenization, "RESTful Data Protection", "Data Protection Gateway", CAKM, CADP, BDT).
- Expiry: alarm at 89 days (daily per node); orange banner 30 days; red banner when any expired (existing licenses keep working). Based on CM clock (UTC if no NTP). Overlapping licenses unsupported except trial. Renew term: generate+add new, then revoke old.
- Trial "CipherTrust Manager Full Trial": 90 days from first start (stop/start/upgrade don't extend; reset keeps original expiry). Covers VCM, CCKM, KMIP, DDC, CTE, LDT, CTE-K8s, CDP Teradata VCL, BDT, DPG, CRDP. Needs admin/System Admins/License Admins group. After purchased VCM license, trial toggle only via CLI/API.
- Enforcement matrix (count/grace): CCKM, CRDP, CTE, CTE-K8s, LDT, CC, RWP, CTE-U, Teradata, SAP HANA, DPG, BDT>=3.x = enforced; CADP centrally-managed (Java 8.18.0) enforced; CADP traditional, CAKM, CDP, CT-V, CT-VL, BDT<=2.5 = not enforced. Grace 90d only for CCKM/CTE-family (term). CRDP/DPG/BDT/CADP: NO grace; existing clients continue, new registration blocked. KMIP: continues in non-compliance mode (warning). DDC: config read-only on expiry.
- Per-connector units: CTE/CTE-U per client (all domains summed; allocated on create incl. migration/GUI/host-register; unregistered client still counts until DELETED). CTE-K8s per worker node w/ CSI attached. RWP per RWP-enabled client (needs CTE base too). CRDP/BDT/CADP per registered client (shared across domains). DPG per application (REST endpoint) w/ >=1 registered DPG. CAKM per DB instance per server node. KMIP per client NODE (shared certs undercounted; LB doesn't reduce need; use unique certs). CDP/CT-V/CT-VL per deployed instance, no monitoring.

### Troubleshooting
- `Error[150]: The specified lock code is invalid.` on add license after reset -> Connector Lock Code changed -> restore backup with old code, or join reset CM to a cluster node holding it, else support.
- Upload error adding VCM license -> used Connector Lock Code instead of Key Manager Lock Code -> regenerate with correct code (support if portal count exhausted).
- `This entitlement belongs to another customer. You are not authorized to use this entitlement.` -> EMS portal error -> Thales Support.
- `License not yet installed for feature CipherTrust Batch Data Transformation` / `...CADP` / `...RESTfuldataprotection` / `...DataProtectionGateway` -> client/app registrations exceed licenses or trial expired -> delete/revoke clients (DPG: remove all clients from application) or buy more.
- `Insufficient Add-On licenses, limit has Reached.` (CADP) -> license expired/exhausted -> install license.
- CTE Used Clients not dropping -> unregistered clients still counted -> delete client from CM. Clients in deleted domain still counted (KY-66351) -> remove DB entries via root shell.
- Banner persists after smaller license applied -> Used Clients > Total; nothing deleted, delete clients.
- Trial deactivate leaves licenses (KY-84562) -> reactivate Full Trial then deactivate.
- Migration log `ignore ... unsupported key size 64 for TDES` / `unsupported algorithm 'RC4'` / `'SEED-CBC'` -> unsupported keys skipped (expected); `fail ... The default IV size must be 16` -> investigate key. Duplicate-data errors on rerun are harmless.
- DSM backup download fails -> DSM CLI `maintenance > repair purgepolicyhistory`, retry.
- `context deadline exceeded (Client.Timeout exceeded while awaiting headers)` on upload -> rerun with `--chunk-size`.
- KS Classic AES-GCM (KY-7288): tag appended to ciphertext in migrated data -> decrypt on KSC, re-encrypt on CM. Local CA signed by external CA fails migration (KY-61054).
- kmip-migration utility errors: `Error loading configuration` -> validate migration.cfg; `Failed to get username and password` -> rerun & enter creds; `Error loading logging configuration` -> restore FLUME var from sample.cfg; `Cannot Initialize DSM handler : <reason>` / `Cannot Initialize CipherTrust Manager handler : <reason>` -> check params for spaces/special chars (wrap in double quotes); `Failed to locate objects on DSM: ...`/`Cannot connect to DSM` -> check connectivity + client cert; `Cannot parse certificate` -> check cert/key path+format or regenerate; `Failed to fetch object from DSM with ID <uuid> -- Retrying : Error` -> 5 retries w/ backoff, ignorable if later succeeds; `... -- Retries Failed` -> inspect cause; `Key Format is not compatible with Algorithm` -> unsupported object; `Failed to create link` -> rerun migration.
- TDPaaS credentials lost -> cannot restore connection without downloaded creds. DDC_TDP_DATA_MIGRATE API errors if scan/report running.

### Troubleshooting
- Support shell `Error: The challenge response was not accepted.` -> bad input (whitespace/truncation), expired (>1 day), or replayed (single use) -> request a new challenge.
- `Unable to fetch username from certificate` -> cert_user_field data/CN absent in cert -> validate cert, fix cert_user_field.
- `No profile mapped with` -> reg token not created from this profile -> recreate token with `-p`.
- `record not found` (CreateKmipClientRegistrationToken) -> profile missing -> create profile first.
- `Invalid Certificate user field` -> use CN|OU|SN|E|UID|E_ND. `kmip profile properties not provided` -> mandatory profile props missing.
- `Unable to create KMIP Client` -> duplicate client name/props. `failed to register client with auth service.` -> bad cert format.
- KMIP profile name conflict -> profile stored as `kmip-<name>` in generic profiles; rename if `kmip-<name>` exists. Client registered without username -> delete in GUI KMIP > Registered Clients and re-register. Email mismatch => Subject DN mismatch.
- `Panic while handling NAE KMIP request` (Terminating KMIP Connection) -> CPU/memory exhaustion -> restart appliance, send syslog to support.
- Auto-registered tls-pw-opt cert rejected in tls-cert-pw-opt/tls-cert-and-pw -> by design; re-register.
- `Key usage mask (<VALUE>) is not compatible with actual usage mask` -> key used for wrong crypto op. `Key is not deletable` / `read on target is not authorized: verdict was deny: ReadKey` / `authorization denied: verdict was deny` -> missing key/user permission. `Failed to locate the public key` -> no read access or key deleted. `Cannot export key in state.` / `Error updating fingerprint in list of keys` -> key Destroyed/Compromised. `Invalid password for pkcs12, it should be base64 encoded` -> base64 the password. `Failed to decode key material` / `Invalid Key Material` -> corrupt key, contact support.
- NAE: `Invalid key state. Key is not in Active State.` -> activate key; `Required field TweakData is missing` / `Error while decoding tweak data` -> FF3-1 needs 7-byte hex tweak; `Encrypt-all supports single data only` -> use DataSingle/Base64DataSingle; `Encrypt update failed on iteration` -> data not multiple of block size; `Error decoding MAC in MACV operation` / `Error decoding Signature in SIGNV operation` -> must be hex.
- `Bad connection` (Create Token) -> LDAP unreachable; `Token has been revoked` -> new token from client creds; `The user does not have permission to authenticate using a certificate.` -> enable cert login; `Failed to validate certificate` -> CA not registered; `Failed to locate domain` -> domain/user missing.
- LDAP test: `Failed to bind to LDAP server` -> bad bind-dn/pw; `[Errno 111] Connection refused` -> bad host/port; `[PEM: NO_START_LINE] no start line` -> Root CA not PEM.
- `Unable to connect to remote cluster member` -> network/firewall; port 5432 must be open. Cluster join with bad hostname -> use lowercase/digits/hyphens.
- `hsm setup is not yet done before adding the hsm server` -> initial setup requires reset (wipes data). `No Luna PCIe cards detected on the appliance.` -> no PCIe Luna. `dial tcp <HOST>: i/o timeout` -> HSM unreachable. `failed to decode PEM data` -> HSM certs not PEM.
- Backup: `Async backup or restore operation is in progress, cannot create backup` / `...cannot restore backup` / `Cannot download backup during an async operation on same backup` -> wait. `Invalid backup scope option` -> system|domain. Restore `Error copying data from backup database` -> key name+version duplicate in target domain: filter backup or delete duplicate. Storage-crunch errors (`Error creating backup directory`, `Error creating temporary directory`) -> free disk.
- `System is already bootstrapped` (Add SSH Key) -> only before bootstrap, one non-default key; `Invalid SSH public key, key type is not valid` -> use ssh-rsa. `Invalid Transport` (syslog) -> udp|tcp|tls.
- After entropy-source/hostname change nothing happens -> `sudo systemctl restart keysecure`.
