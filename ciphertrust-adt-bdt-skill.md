# CipherTrust Application Data Protection and BDT

## T-Mobile context (read first)
- **Version:** T-Mobile runs CM 2.23, upgrading to 2.24 in early December 2026. This reference was distilled from the 2.25 ("latest") docs, so features, fields or endpoints may not exist yet on 2.23/2.24. Say so when a detail is version-sensitive.
- **/v1/data-protection** serves CADP, CRDP, BDT 3.0 and CTDP clients and policies. **/v1/client-management** is a separate API for system-registered clients. Both are used, for different things; do not substitute one for the other.
- **Ignore BDT 2.x (legacy):** the "BDT/*" tag endpoints (bdt-policies, containers, protection-profiles) and the legacy BDT policies material are not used. Only BDT 3.x applies.
- **Ignore anything marked deprecated** (e.g. /v1/protectapp profiles and clients).
- DDC and Secrets Management are out of scope.

## ADP and BDT

### Reference
**ADP model (docs v2.25; T-Mobile runs 2.23).** GUI: login > Application Data Protection tile. Central mgmt: admin defines Application (= client profile, container for clients) -> registration token -> client registers (gets cert+key; auths with JWT) -> pulls config+policies; changes picked up on heartbeat. Connector types: CRDP, DPG, CDP for Teradata VantageCloud Lake, CADP for Java, BDT (3.0.0+), CAKM for Oracle TDE. Policy changes bump version; client with stale version refetches on heartbeat. Single Pane of Glass = Applications page; app status = worst client (Error > Warning > Healthy). Per-app token is unique, never expires by default, reusable for many clients of that app.
**REST (base /v1/data-protection; API Playground > Data Protection):**
- client-profiles (apps): POST/GET list (name,skip,limit,sort)/GET {id}/PATCH {id}/DELETE {id}. DELETE app deletes all its clients.
- dpg-policies POST; data-sources POST/GET/GET {id}/PATCH/DELETE; bdt/job-configurations POST/GET/GET {id}/PATCH/DELETE; bdt/job-configurations/{id}/run POST (body: client profile id); jobs/{id}/stop|resume POST; jobs/{id} DELETE
- character-sets POST/DELETE {id}; user-sets GET/GET {id}/POST/DELETE {id}; masking-formats GET/POST/PATCH/DELETE {id}; access-policies GET/POST/PATCH/DELETE {id}
- protection-policies POST/GET/GET {name}/PATCH {name}/DELETE {name} (addressed by NAME, not id)
- database-instances POST (CAKM, API only); database-clients GET, PATCH {id} (body client_profile_id)
- Client-side: /v1/client-management/self/client/renew (cert auto-renew; this is the path in the 2.23 developer API spec. The docs PDF shows /v1/data-protection/self/clients/renew, which is NOT in that spec, so verify on the target version); /api/v1/data-protection/clients/get-updates?updated_after=<UTC> (documented in the docs but NOT in the 2.23 developer API spec; may be a newer or client-facing endpoint, so verify before relying on it) (CRDP etc. w/o app policy; response flag count_mismatch=false: resources exist, cache updated; true: missing resources deleted from client cache; omit updated_after -> all resources)
**Client config defaults (common):** Log Level WARN (INFO|WARN|ERROR|DEBUG); Key Cache Expiry 43200 s (min time key cached); Heartbeat Interval 300 s (min 5, recommend >30); Heartbeat Timeout Count default 5 (-1 = never revoked/never unhealthy); Certificate Duration 730 days; Certificate Auto Renewal off; Local CA = CipherTrust Root CA (root or domain CA); Client Groups default "Application Data Protection Clients"; Performance Metrics toggle on (CRDP/DPG). CSR params: Common Name (user that talks to CM), City/Country/State/Org/OU/Email (mandatory for DPG, optional others). CM recomputes client status every 5 min. Revoked = missed hb count = TimeoutCount*interval, or cert expired (licenses released; both listed as "Revoked"). Warning = skipped heartbeat (still operates). Error = client self-reports, cannot process. CAKM: no Revoked state; Error when missed > count, auto-returns Healthy on heartbeat.
**CRDP:** Connection Idle Timeout 300 s (opt), Connection Timeout 10000 (opt). JWT Verification (toggle, default enabled) via Public Key tab (PKCS1/PKCS8 pem) or JWKS URL tab (default toggle off; JWKS URL must be public trusted CA, TLS or non-TLS; custom CA NOT supported; refresh Duration default 7 days). Issuer: comma-separated no spaces; mandatory when multiple IDPs ("Add More JWT"). Username location in JWT default `sub` (access policy applies to that user; if JWT verif off and unset, username from request body of /v1/reveal or /v1/revealbulk). Enable DPoP (default off): DPoP-bound token, proof via DPoP header.
**DPG:** Auth scheme Basic(default)|Bearer; Token Field (Bearer only) = username claim for reveal access control. TLS Enabled not configurable; TLS Skip Verify always on. DPG<=1.2 (NAE-XML iface; needs NAE iface TLS+verify client cert+username from cert+auth optional; Common Name = DPG user) extra: MaxIdleConn 10000, MaxIdleConnPerHost 10000, Dial Timeout 10, Dial KeepAlive 10, Conn Idle Timeout 600000, Conn Retry Interval 600000, Conn Timeout 60000, Read Timeout 7000, Pool 300, LB round-robin|random. DPG>=1.3 (REST iface): Conn Timeout 60000 + heartbeat. DPG policy per app: endpoint URL + method (POST/GET/PUT/PATCH/DELETE) + tokens(Request/Response): Name (JSON path or URL param), Location JSON|URL, Operation Protect|Reveal, Protection Policy, External Version Header name, Nonce Header name, Access Policy (reveal). Array path: `CreditCard.[*].CCNumber`. Reveal with same protection policy used to protect.
**CADP Java:** Log Rotation Daily(default)|Weekly|Monthly|Size|None, Log File Path default CADPLogs.txt, Log Size Limit 100K, Log Max Backup Index -1, Log GMT (rotation editable only via API). **CDP Teradata VCL:** Connection Timeout 10000. **BDT:** Batch Size 1000, Thread Count 1. **CAKM Oracle TDE:** Log Rotation Daily|Size, Log Size Limit 100K, Log File Path default Linux /opt/CipherTrust/CAKM_for_Oracle_TDE/logs/pkcs11.log (absolute, .log, not root dir, same for all CDB/PDB of instance); config comes from CDB's app (keep PDB apps identical); don't change assigned group later.
**Protection policy** (Policies > Protection Policies). Key: symmetric/asymmetric, must be exportable + in group w/ Read, Encrypt, Decrypt, Export (e.g. ADP Clients); app Client Groups must contain that group. Algorithms: FPE/FF1v2 (recommended FPE), FPE/FF3, FPE/FF3-1 (input len <= block size), FPE/AES; AES/CBC|ECB x NoPadding|PKCS5Padding, AES/GCM (recommended AES; NoPadding, random nonce mandatory internal|external; AAD; TagLen 32-128 bits multiple of 8), AES/CTR (16-byte IV), Random2 (vaultless codebook tokenization, Thales proprietary, PCI), DATEv3 (vaultless date tokenization), RSA/PKCS1Padding|PKCS10AEPPadding[SHA256|384|512] (1024-4096), EC ECIESwithSHA{224,256,384,512}/AES/CBC/{PKCS5Padding|NoPadding} (curves secp224k1,secp224r1,secp256k1,secp384r1,secp521r1,prime256v1,brainpoolP{224,256,384,512}{r1,t1}). Key sizes AES/FPE 128/192/256. No vaulted tokenization in this section (BDT mentions CTS token template/group).
- FPE/Random2 need character set (UTF-8 hex ranges, e.g. 0370-03FF,0031-0039; immutable once created; predefined can't be deleted: Lower Alphabets 0061-007A, Alphanumeric, Printable ascii 0021-007E, All digits 0030-0039). FPE min input 2 chars (3 w/ Luhn); Random2 1 (2 w/ Luhn). Luhn only w/ All digits; don't use with static masks preserving last digits. Allow Small Input: passes through short input unchanged, else error `Input buffer is too short (len=1), it has to be at least 2 bytes long.`; null/"" always passed through.
- Prefix <=7 printable ASCII. Tweak (FPE only, needs random nonce Disable): algo SHA1|SHA256 (<=256 chars), NONE (16 hex FF1v2/FF3/FPE-AES; 14 hex FF3-1), NULL (not for FF3 variants). DATEv3 tweak 16-64 chars; Start/End Year (start>=1000, end<=9999, end>=start, span<=999y, 2-digit-year formats same century); formats DDMMMMYYYY DDMMMYYYY MMDDYYYY MMMMDDYYYY MMMDDYYYY DDMMYYYY MMMDDYY YYYYMMDD DDMMMYY YYMMDD MMYYYY DDMMYY MMDDYY MMYY; delimiters / . - space (one only); first matching date tokenized.
- Random nonce Internal (ciphertext = version header+prefix+nonce+ct; use w/ internal|disabled versioning) | External (separate field; external|disabled versioning) | Disable. Algos: AES CBC/GCM/CTR, FPE all. AES CBC/CTR IV mandatory when nonce disabled. FPE/AES IV hex, each byte 00..cardinality-1, len=block_size=2*floor(log10(2^96)/log10(card)) (card 10:56, 26:40, 62:32, 94:28); used only if input > block size.
- Irreversible token (AES/CBC, FPE all; not Random2/DATEv3/GCM/CTR/ECB/RSA/EC): reveal returns same value (e.g. 1234567 -> 10010003108044 -> reveal 3108044); no tweak/IV allowed.
- Versioning: Internal (7-digit header 1001000-1999999 prepended: digit1 type, 2-4 policy ver, 5-7 key ver), External (header in separate column/field), Disabled (no header, policy not editable, only key version 0). Type & name immutable; protect uses latest version, reveal uses version in header; only latest version editable; delete removes all versions. Key states: Pre-Active none; Active protect+reveal; Compromised reveal only; Deactivated none; Destroyed none.
- Legacy FPE/{AES,FF1v2,FF3}/CARD10|CARD26|CARD62|ASCII|UNICODE auto-mapped on edit to algo + All digits|Lower Alphabets|Alphanumeric|existing set. Upgrading from CM<=2.13 to 2.14+: must link an access policy to each protection policy.
**Masking** (Policy Elements > Masking Formats; immutable create-only except custom PATCH; predefined undeletable). Static (at protect; FPE, Random2 char; DATEv3 date; preserve first/last N, max 2 date parts). Dynamic (at reveal; mask char default X; show/mask first/last N). Predefined static FIRST_SIX, FIRST_SIX_LAST_FOUR, FIRST_TWO_LAST_FOUR, LAST_FOUR; dynamic SHOW_FIRST_SIX, SHOW_FIRST_SIX_LAST_FOUR, SHOW_FIRST_TWO_LAST_FOUR, SHOW_LAST_FOUR.
**Access policy:** user-set rules (ordered; index 0 highest priority; user in several sets -> first match) + default reveal format for users in no set. Reveal formats: Plaintext | Ciphertext | Error Replacement Value (NULL or custom) | Masked Value (+masking format). User set = users/groups (Policy Elements > User Sets). Must be linked to protection policy.
**Key access:** keys belong to groups; client -> app -> client groups -> keys. Groups: Application Data Protection Admins (CRUD ADP, read keys), ADP Clients (read-only, default for new clients), All Clients, custom. Least privilege: dedicated group, assign key only there, remove key from ADP Clients group (wizard-created keys land there; Keys-menu keys land in admin group).
**BDT data sources** (Data Sources; names case-sensitive): DB types Db2, Oracle, SQL Server, MySQL, SAP HANA, PostgreSQL (Connection URL JDBC, JDBC Driver Download URL under /opt/app/tmp, DB CA cert, user, pass); files CSV (Delimiter `,`, Qualifier `"`, must differ, no backslash; Encoding UTF8, ibm500 for EBCDIC; Column Count; Has Header Row fixed on) or Fixed Length (Record Length, Column Position Info start/end from 0, end exclusive; Line Separator). Type can't switch DB<->file or CSV<->FL. Job config: Name, Unprocessed Record File Path (file `<job_id>-<source_table>-<timestamp>.txt`; sensitive), modes File-File/DB-DB/DB-File/File-DB; Subset Offset 0, Limit 0, Recurrency 1, Order By/Order (DB); Filters selector/operator/expression; column Operation Protect|Reveal|Reprotect, Source Column Action PRESERVE|EMPTY|REMOVE, Protection Policy, Version Header Column, Random Nonce Column Name; Same as Source = in-place (subset/filter ignored); Create Destination Table; fixed-length dest only FPE. Job states: Initiating, In Progress, Completed, Stopping, Stopped. Stop only Initiating/In Progress; delete Initiating/Completed/Stopped.

### Workflows
1. Define app: ADP > Applications > Add Application > General Info (unique Name, Connector Type) > Settings (client+server config) > [DPG: Policy/Add Endpoint] > Save; copy Registration Token (shown once at creation) -> client Quick Start registers. API: POST /v1/data-protection/client-profiles.
2. Modify app: Applications > name > Settings tab > Update (PATCH client-profiles/{id}); clients pick up on next heartbeat. Cleanup: app page > Remove Revoked Clients; Refresh Client icon refreshes status.
3. Protection policy: create char set (FPE/Random2) > masking format (opt) > user set > access policy > Policies > Protection Policies > Add: Name, Algorithm, Key (exportable), Character Set, Masking Format, Access Policy, review > Create. Edit = new version, auto-pushed after heartbeat.
4. BDT: create/ensure data source(s) + protection policy -> BDT Jobs > Job Configurations > Add Job Configuration -> app page "Run Job Now" or config overflow > Run Job Now (needs active client registered to BDT app) -> BDT Jobs > Job Status; Stop/Resume/Delete from overflow. First BDT client heartbeating runs job with latest config.
5. CAKM Oracle TDE: POST database-instances (app_connector_type, name, client_configurations XOR database_instance_id, database_clients[client_type CDB|PDB, client_mode united|isolated, names exactly as in Oracle]); copy database_instance_id + client_configuration_id -> POST client-profiles (app_connector_type, name, client_configuration_id) -> GET database-clients, PATCH database-clients/{id} {client_profile_id} for CDB and isolated PDBs -> `ADMINISTER KEY MANAGEMENT SET KEYSTORE OPEN IDENTIFIED BY "<Registration token>";`. United PDBs reuse CDB token; isolated PDBs reuse CDB token or own token+app. RAC: clone instance once per node (POST database-instances with database_instance_id); clones follow source config. Migration v8.x->9.1.0: restore keys (MEK/opaque objects exportable), create instance+profile, associate, assign same group to MEKs+opaque objects, opaque object DATA_OBJECT_SUPPORTED_IDEN -> group Application Data Protection Clients.
6. Cert auto-renew: toggle Certificate Auto Renewal in app CSR params; client calls the renew endpoint (see REST section for the path caveat); otherwise manual per client docs.

### Troubleshooting
- Client shows Warning -> missed heartbeat(s) (network/CM down) -> restore connectivity; still operates. Revoked -> missed count reached Heartbeat Timeout Count or cert expired; no crypto, license freed -> re-register with app token; set Timeout Count -1 to never revoke.
- CAKM clients Error after DB reboot with CM unreachable -> delete Error clients in UI to get accurate status.
- `Input buffer is too short (len=1), it has to be at least 2 bytes long.` -> input below FPE min -> enable Allow Small Input or lengthen (Luhn: 3 FPE / 2 Random2).
- Reveal returns same ciphertext/value as protected -> Irreversible Token enabled, or access policy reveal format = Ciphertext / user not in intended user set (default reveal format applies; first matching set wins).
- Reveal gives masked/NULL/custom value -> access policy rule or Error Replacement Value; check user set order and JWT username location (`sub` default).
- Protect/reveal denied for key -> key not exportable or key not in app's Client Group w/ Read/Export/Encrypt/Decrypt; key state must be Active (Compromised reveal-only).
- Can't edit protection policy -> versioning disabled, or editing an older version (only latest). Can't change name/versioning type.
- JWKS URL fails -> custom-CA JWKS not supported; use public CA or Public Key tab. Multi-IDP JWT fails -> Issuer required, comma-separated, no spaces. JWKS refresh default 7 days. (No CRDP numeric error codes or "unable to look up kid" text in this source.)
- Luhn output not Luhn-valid -> static mask preserves last digits; use mask not preserving trailing digits.
- Random nonce/version header mismatch -> Internal nonce needs internal|disabled versioning; External needs external|disabled; reveal must use same policy/version as protect.
- BDT job Resume fails after Stop in Initiating -> delete job and rerun. Resumed job stays Initiating until a BDT client picks it up. Run Job Now disabled -> no active running client/association. DB object not found -> names are case-sensitive.
- Cannot change data source DB<->file or CSV<->Fixed Length -> create a new data source.
- Deleting app removes all clients (outage risk). Client registration fails if cert is CRL-revoked (audit record logged).
- DATEv3 error "no dates matching" -> input must start with date in policy format with one supported delimiter; year within Start/End.
