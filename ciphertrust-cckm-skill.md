## CCKM (AWS, Azure, GCP, DKE)

### Reference
**Coverage (07_cckm_a):** CCKM intro/overview, proxy/DNS/port, AWS KMS (+CloudHSM, XKS/HYOK, XKS perf), Azure (+Stack, certs, secrets, templates, backups), Microsoft DKE, external CipherTrust domains/keys, DSM, Google Cloud CMEK (projects/keyrings/keys/reports/schedules). NOT in this range: OCI, Salesforce, SAP, Google EKM/Workspace CSE, Luna partition mgmt, Connection Manager, REST API ref (see other parts).
**CCKM basics:** flow = connection (must be Ready) -> container (AWS acct / Azure vault / CM domain / Luna partition / DSM domain / GCP keyring / SFDC org / SAP group / OCI vault) -> Refresh (downloads keys; can take hours/days) -> manage keys. Clouds: AWS (+GovCloud, China), Azure (Public, China, US Gov, Stack AD/ADFS), GCP, OCI, SFDC(+sandbox), SAP DC. Key sources: CM local, external CM, Luna 7.3+ (RSA-4096 import 7.4+; FM-enabled Luna NOT supported), DSM 6.4 CP3+ (EOL Jun 2024, deprecated), Azure Dedicated HSM. Roles: system groups "CCKM Admins" (also need Key Users, Connection Admins, User Admins) and "CCKM Users" (per-resource ACLs; default view-only; ACL changes via Assign User/Group). Reports: Key Activity, Key Aging, Service/Usage (none for Azure Stack). Web port: change from 443 BEFORE configuring XKS/Google EKM/CSE/DKE/OCI EKMS/SFDC cache-only (unsupported after); AWS XKS+Google only talk on 443 -> LB/firewall mapping 443->custom; CSE/DKE/EKM take host:port (example.com:8443). Proxy: HTTPS proxy, add proxy CA under Trusted CAs (2.22+). Whitelist: AWS logs/ec2/iam/kms/sts.<region>.amazonaws.com(.cn); Azure management.azure.com, login.microsoftonline.com, vault.azure.net, *.managedhsm.azure.net, api.loganalytics.io, graph.windows.net (Stack), graph.microsoft.com (DKE); GCP oauth2/cloudresourcemanager/cloudkms/logging.googleapis.com. AWS VPC endpoints: IAM unsupported; add endpoint IPs for sts/ec2/logs/kms via Admin Settings > DNS Hosts > Add DNS Host. Metadata CSV export max 100 accounts/vaults.

Basic format = repeats daily|weekly|monthly|yearly + at (UTC); cron = minute hour dom month dow. Rotation scopes: All Keys / Only Expiring Keys ("rotate keys within _ of material expiration") / by age since creation-last rotation (default 7 Days). Options: new-key expiry, "Rotate Key Material (Imported AES Keys)", "Apply Gravestone Alias on Current Key" (`<alias>-rotated-<timestamp>`). Description max 250 chars. It will take a few seconds to finish." Bulk enable/disable/delete create a Job (Bulk Operations tab).

### Workflows
1. AWS onboard: Access Management > Connections Management add AWS conn, Test (Ready) -> Cloud Key Manager > KMS Containers > AWS KMS Accounts > Add Account (name, connection, regions; optional Assumed Role + Test Connection) -> Refresh -> Cloud Keys > AWS > Add Key.
2. AWS BYOK: Add Key > account/region > Origin External (BYOK) > source > regionality > source key (create/copy) > alias/tags/expiry > policy > schedule > Add Key; Decide Later -> PendingImport -> Import Key Material.
3. AWS HYOK: AWS (+Luna) connections -> AES-256 health check key -> account > External Custom Key Stores > + Add External Key Store -> Download credentials -> Linked: Connect; Unlinked: Link or create in AWS KMS manually -> Cloud Keys > AWS > Add Key > External Custom Key Store (HYOK) -> if unlinked, Link Key or make KMS key using XKS ID. Rotate = Add Version (Rotate); suspend = Block.
4. XKS credential rotation: store details > Add Credential > Download -> Connect (linked) or upload to AWS console (unlinked) -> Delete Credential for old; or Credential Rotation schedule assigned on local+linked store.
5. AWS org discovery: mgmt IAM user + member role + StackSet -> connection -> Schedules > Add KMS Container.
6. Azure: register app, Reader, API perms, consent, vault perms -> Azure connection -> KMS Containers > Azure Key Vaults > Add Existing Vault (Managed HSM box for HSM pools) -> Cloud Keys > Azure > Add Key.
7. Azure restore purged key: Cloud Keys > Azure > key > BACKUPS > Restore Backup (same-region vault); if vault deleted in portal, recreate same name/region and refresh first.
8. DKE: prereqs -> Services > Microsoft DKE; create Authorized Tenant -> Create Endpoint (name, Key URI Hostname, KEK, tenant) -> register Azure app -> Purview sensitivity label (Use Double Key Encryption + DKE Endpoint URL) + label policy.
9. DSM/CipherTrust/Google containers: add connection -> KMS Containers > DSM Domains | CipherTrust Domains | Google (Add Existing Project / Add Existing Key Ring: connection, project, location) -> Refresh -> Cloud Keys.
10. GCP key: Cloud Keys > Google > Add Key > Create/Upload New or Clone Existing > source > destination (name, keyring, protection, rotation) > schedule > Add Key; rotate = Add Version; destroy = Schedule Destruction (cancel within wait time).

### Troubleshooting
- AWS permission error right after granting IAM -> propagation delay -> wait, retry.
- Cannot add AWS conn/keys in VPC -> no public EC2/KMS/Logs/STS -> add VPC endpoint IPs in Admin Settings > DNS Hosts; CM in VPC with account outside us-east-1 needs STS Regional Endpoints.
- AWS key greyed out -> permissions/connection/region changed -> fix access, refresh.
- On-demand rotation refused -> AWS limit (default 10) or key not SYMMETRIC_DEFAULT.
- BYOK rotation fails -> reused key material -> supply new distinct material.
- Primary key deletion blocked -> delete replicas first.
- CloudHSM connect fails -> kmsuser logged in on cluster or password not reset after prior connect; edits need Disconnected state.
- XKS secret key lost -> shown once -> Add Credential, redownload; AWS rejects path -> remove /kms/xks/v1 suffix.
- Linked XKS create fails connection test -> VPC endpoint/DNS/cert CN/443 not ready; mTLS no longer supported by AWS -> disable mTLS.
- XKS slow/timeouts -> HSM latency >25ms or AWS latency >35ms, success audit events on, undersized CM.
- Remote-type store: health check key/max credentials not editable.
- Refresh "This may take a while..." -> normal; Cancel Refresh discards progress.
- Azure multitenant vaults not listed -> admin consent URL not granted or Lighthouse missing.
- Azure vault absent with Private Link -> DNS resolution -> add DNS Host.
- Azure key delete fails -> soft-delete vault needs Soft Delete then Purge (needs both perms).
- Azure upload slow -> Azure-side throttling.
- DKE decrypt denied -> issuer mismatch (trailing slash), UPN/email not authorized, role connection tenant != issuer; label up to 24h; DKE endpoint delete needs Archive first.
- DSM key create fails -> domain full, bad/expired creds, domain admin != connection admin, expiration not in future.
- GCP destroyed version -> re-import API (needs Import Failed|Destroyed + eligible); GCP throttling -> raise Cloud KMS quotas.
- Saved AWS policy cannot be deleted -> Verified (attached to key).

### Troubleshooting
- Salesforce BYOK upload fails -> derivation setting mismatch or cert not 4096-RSA BYOK-compatible -> align "Allow BYOK to Opt Out of Key Derivation" / supply compliant cert.
- SAP connection `Credential must only be refreshed once` -> tech user credential generated with Activate Now=YES -> regenerate with NO; first Test Connection fails by design, save, then re-test saved connection.
- GW CSE `invalid authorization token - cause: untrusted authentication token: square/go-jose/jwt: validation field, token issued in the future (iat)` -> clock skew -> add Google NTP in Admin Settings > NTPs.
- EKM UDE log `unable to check validity of instance key...` -> no connection with SA holding `compute.instances.getShieldedInstanceIdentity`; wraps still proceed.
- EKM breaks after port/cert change -> port change after config unsupported; restart CCKM service after web cert change; UDE cluster nodes need identical cert.
- Luna `connection_status` not `connection ok` -> CM not authenticated, NTLS down, or partition not assigned to client; check HSM logs. Key create fails: partition full or bad/expired HSM credentials. Export/Clone mode mismatch -> wrap key error.
- Delete OCI IdP: `Error in deleting identity provider` -> issuer still tied to external vault; change association first.
- OCI EKMS dead after CA/IP change -> private endpoint CA/IP immutable; rebuild OCI setup. External vault hostname must be IP (FQDN unsupported).
- Adding already-added vault/group/org -> error (add once only).
- Refresh All (Luna/SAP) can take hours/days; runs in background (Cancel Refresh).
- SAP non-exportable key delete irrecoverable; Oracle key restore requires backup.
- Google Cryptospace on non-443 port unsupported by Google -> front with LB mapping 443.

## CCKM REST API

### Reference
- Source: CCKM API (CM v2.25). Doc note: "APIs might change from version to version. Refer to the API playground URL of your CipherTrust Manager for updated APIs."
- Base: `https://<CM_FQDN>/api/v1/cckm/<provider>/...` (doc prose abbreviates as `/v1/cckm/...`). curl uses `-k`, `-H 'Authorization: Bearer AUTHTOKEN' -H 'Content-Type: application/json' --data-binary '{...}' --compressed`.
- Auth: get JWT via `POST /api/v1/auth/tokens/` (body grant_type=password, username, password); JWT short-lived (~5 min in samples). Non-CCKM: `/api/v1/vault/keys2`.
- Status: 2xx success, 4xx client error, 5xx server error (no per-code table in this doc).
- List params (GET collections): `skip` (offset), `limit`, `sort` (comma list, `-field` = desc, e.g. `name,-createdAt`), plus filters e.g. `cloud_name`, `kms`, `region`, `source_key_tier` (local|luna-hsm), `custom_key_store_type` (EXTERNAL_KEY_STORE|CLOUD_HSM).

### Troubleshooting
- 401 / expired token: JWT lifetime is minutes; re-POST `/api/v1/auth/tokens/` and retry with new `Authorization: Bearer`.
- Rate: "CCKM sends an error message, if the rate of requests exceeds this limit." (per-key-store requests/second limit) -> throttle/retry.
- Custom key store errors: linked -> "make sure the VPC or private network elements are working"; unlinked -> "check for network access issues"; if interfaces can't receive requests, restart services or re-configure.
- Key store credential auto-rotation needs the store in linked state so new credentials update in AWS KMS.
- Cloud resources deleted outside CCKM / out-of-date: POST `synchronization-jobs` or `keys/{id}/refresh`; items flagged `"gone": true`.
- HMAC keys unavailable in cn-north-1 and cn-northwest-1.
- Doc has no enumerated error-code table; consult playground (Swagger) at CM for per-API codes.
